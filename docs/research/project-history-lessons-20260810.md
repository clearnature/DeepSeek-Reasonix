## 三、反复出现的教训模式（跨阶段归纳）

1. **「golden 差异 ≠ bug」**（dype 7/29-31，至少 3 次犯错）：路径/包名/环境噪声被当代码缺陷修，白改后回退。正确：先 diff 原版、分类噪声 vs 逻辑，噪声走 filter/`--accept`。
2. **「环境乱动 vs 只改数据」**（dype 7/31）：动 .envrc/RUNGHC/GHC_PACKAGE_PATH 反复折腾；删 dist-newstyle 全量重编。正确：构建失败先查缓存与环境，不删缓存、不改环境。
3. **「估算口径不一致」**（8/9-8/10，最昂贵教训）：tokPerChar 分子/分母不对称、fold 用 raw 口径 src 用校准口径 → 子集>超集假象。正确：展示/遥测全校准、决策层保守，且必须对称。
4. **「先实测后下结论」**（8/3、8/7，MiMo 三个错误判断均被 API 实测推翻）：猜协议不如抓原始 SSE、读官方文档。
5. **「修 bug 先核对运行版本」**（8/9）：「40% 提前压缩」根因是用户跑旧构建，修复早已提交。
6. **「遥测必须落盘」**（8/8）：只进 UI 的事件事后无法归因，是打穿定位耗时根因。
7. **「删除代码未经确认」**（8/4 割裂 PR 误删共享文件）：共享基础文件两分支都带，先验证再删。
8. **「merge 后必须真实操作验证」**（8/10）：重复 emit 这类隐藏产物靠手动 /compact 才暴露。

## 四、有效的方法论（跨阶段证明有效）

- **数学实证替代争论**：打穿 93% 吻合、CompactionBench 定价（448k→76k）——数字说话。
- **diff 对齐原版**：dype 改任何配置先 diff Agda 原版；同步先侦察（27 冲突文件清单）再执行。
- **四验证链**：gofmt→vet→repolint→全量测试→golden 重生成→wails build，堵住 CI 往返。
- **记忆沉淀**：关键决策立即落 memory 跨会话恢复；方法论（如 desktop-wails-build-command）固化为可复用指令。
- **守卫测试契约**：`TestCacheHitSurvivesTooSmallWindow` 等把哲学变成可执行断言。
