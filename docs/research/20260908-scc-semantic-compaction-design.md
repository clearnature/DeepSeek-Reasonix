# SCC：语义连通压缩设计（Semantic-Connectivity Compaction）

> 状态：设计提案 v0.1（2026-09-08）
> 灵感来源：Sovereign 权重稀疏实验的渗流理论（/data/模型训练精度验证）
> 目标：把「Backbone 保连通 → 低保留密度高压缩」机制迁移到 Reasonix 上下文压缩

---

## 1. 背景与动机

### 1.1 现有上下文压缩的三个缺口

| 缺口 | 现象 | 代码锚点 |
|------|------|----------|
| **无语义连通监控** | 折叠只按位置（head+N 窗口），压深后主题链断裂 → 模型遗忘/幻觉 | `partitionFold` 位置策略 |
| **无重要性分层** | periphery 与关键决策链同权重折叠 | `partitionFoldForProjection` |
| **压完即信** | 无回检——产物是否语义完整无验证 | 压缩遥测只有 token/spans 无语义指标 |

### 1.2 灵感：Sovereign 渗流实验（本地一手证据）

- V3.1 实测：无结构稀疏过 ~24%（保留密度）→ 有效连接图碎裂 → 泛化崩塌（Val Loss 6.52）
- V4.0 修正：**Backbone 连通脚手架**（15% Block 永不剪）→ 任意稀疏度下保持图连通、梯度可回传 → 保留密度可压到 2-5% 档（20-50× 压缩）而不碎裂
- 推论迁移：**上下文折叠 = 稀疏化**；**信息骨架（Backbone）= 主题实体-事件链**；**碎裂 = 语义孤岛化**（摘要中某主题链断裂不可回溯）

## 2. 映射表

| 权重压缩机制 | 上下文压缩对应 | 现有体系对应物 |
|---|---|---|
| 渗流阈值（连通碎裂点）| 折叠深度安全线：主题图保持巨连通的最大折叠率 | 无（现无主题图）|
| 15% Backbone 连通脚手架 | **主题骨架消息 verbatim 永不折叠** | A1「摘要永不再次折叠」是文档级；缺主题级 |
| Block 重要性 = Σ\|g\|×Σ\|a\| | 块重要性 = 任务相关性 × 信息密度 × 引用度 | B2 只按位置保留小 turns，无重要性 |
| 渐进 ramp（5%→50% 保留）| **压缩比分级档**（保守 0.5 ↔ 深度 0.02-0.05）| 压缩比由窗口被动触发 |
| 拓扑熔断（Gap>1.0 锁稀疏）| **语义碎裂熔断**：产物主题覆盖回检失败 → 提高保留档重试 | 无 |
| Muon 正交化 | （远期）骨架向量与摘要向量正交，避免主题污染 | 无 |

## 3. SCC 机制设计

### 3.1 五步流程

```
输入：折叠区 msgs[head:start]
 1. 骨架抽取     → 主题图 G（实体→事件/决策/任务引用链），Top-15% 节点 = Backbone
 2. 块分类       → backbone 块（verbatim 保留）/ periphery 块（可折叠）
 3. 折叠         → periphery 块走现有 foldSummaryWithChunkedFallback（冻结工具链复用）
 4. 渗流回检     → 产物主题覆盖校验：每骨架主题链在产物可回溯？断裂 = "碎裂"
 5. 分级/重试    → 碎裂 → 提高保留档重试；通过 → 输出（backbone verbatim + periphery 摘要）
```

### 3.2 主题骨架抽取（草案）

```
主题图节点 = 折叠区实体（文件/符号/决策/任务 id），边 = 消息间引用
节点重要性  = 任务上下文相关性 × 跨块引用度 × 信息新鲜度
骨架(Backbone) = Top-15% 节点 + 其连通路径上必需的桥消息
骨架块 verbatim 保留（等价永不折叠）；periphery 折叠成摘要
```

### 3.3 渗流回检器（草案）

```
回检指标：
  - 覆盖率 C = 可回溯骨架节点 / 总骨架节点（阈值下限）
  - 连通率 K = 骨架主题链完整延续数 / 总链数
熔断：C < C_min 或 K < K_min → 报"碎裂"，保留档 ×2 重试（上限保护）
目标：把「压完即信」改为「压完可证」
```

### 3.4 压缩比分级档

| 档 | 保留比例 | 适用 | 对应现有 |
|---|---|---|---|
| conservative | 0.5 | 近期/活跃任务 | B2 保留 |
| standard | 0.2 | 默认折叠 | A1 摘要滚动 |
| deep | 0.05-0.02 | 超长历史冷段 | 需新增 |

## 4. 与现有体系兼容性（红线）

- **前缀字节稳定**：骨架块与摘要都在折叠产物固定位 append，系统提示词/tool 前缀零变动——SCC 只在折叠区内加分层
- 复用现有：`foldSummaryWithChunkedFallback`（chunked/400 修复链）、冻结 tools（savedMainRequest）、投影 realign
- 不删代码：新文件承载 SCC（上游无路径独立文件 + 守卫测试——防丢失模板）

## 5. 冒烟测试计划（假说先行）

| # | 假说 | 测试 |

## 6. 历史数据测试计划

- 数据：stats 已记录的真实压缩会话（1.16M 400 故障会话 / 38 万成功会话 jsonl）
- 对照：现有 compaction 产物 vs SCC 各档——token 压缩比 × 语义得分（人工抽样 + 回检指标）
- 验收：deep 档达 20-50× 且回检通过（无碎裂）→ 渗流迁移成立

## 7. 风险与边界

- **语义打分主观性**：回检器用「可回溯引用」客观代理（非 LLM 评判），避免主观
- **骨架抽取成本**：主题图构建是额外开销——只对折叠区做，预算受限
- **与 A1 摘要冲突**：骨架 verbatim 增加保留量——需验证净压缩比仍达标
- **50× 上下文压缩的语义边界**：50× 只适用冷超长段；近期活跃段必须保守（否则工作状态丢失）
