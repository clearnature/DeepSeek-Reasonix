### 5.2 文本无冲突 ≠ 语义无冲突

本轮最危险的一处（import cycle）**不在** `git merge-tree` 报告的 14 个冲突文件里——它由"上游给 A 加空白导入 + 本地 A↔B 反向依赖"合成。**合并后必须立即 `go build ./...` / `go test` 全量**，不能只看冲突清单。

### 5.3 上游新增测试 vs 本地机制的冲突，按"上游设计意图"裁决

本轮 3 例（fork ID、jobs 信封断言、head notice 顺序）都是"上游测试假设 + 本地机制"的碰撞。裁决原则：先查该测试/语义是否上游**有意变更**（`git show <tag>:<file>` 对比 + 该测试在 upstream 是否仍在），再决定改测试还是改代码。**改测试必须写明理由**，不得为通过而放宽断言。

### 5.4 B2 的准确边界（本轮教训）

`planFoldRegion` 的 `splitActive`（= `mustFree`，即 `trigger==overflow || est >= hard`）分支允许**折入 active turn 的较早已完成回合**；常规 `pressure` 折叠仍是**位置固定**（`start = active`）。**该分支是超窗救援的必要条件，删除它会导致 `CompactionNoop` → 压缩永不发动。**

> B2（保留窗口按位置固定）约束的是**常规折叠**；已超窗救援路径不存在"可复用前缀"，因此允许折入。**勿再以 B2 为由删除该分支。**

### 5.5 桌面预算必须按 dev 增量校准

合并后 `wails build` 会在 `check-bundle-budget.mjs` 失败（上游 budgets 不含 dev 前端增量：context ring、locales）。按实测取**下一个十分位**校准，并在注释里记录实测值。

### 5.6 子代理结论必须复核

本轮 4 名研究员产出中发现：基线口径错（用了 `origin/main-v2` 的 492 提交/3269 文件而非 `v1.38.3` 的 302/1349）、引用了**不存在的 v1.38.4**、把真实存在的 `fast_compress` 判成"死符号"。**采纳子代理结论前必须自己复跑其命令。**
