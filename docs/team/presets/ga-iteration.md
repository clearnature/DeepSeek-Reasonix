# 遗传算法迭代框架（docs/team/presets/ga-iteration.md）

> 15 智能体 #3 决策 + **devil's advocate 修正（A1）**：
> GA 的搜索空间被前缀红线锁死（6/9 位点敏感）、适应度在饱和基线上接近噪声、10 代成本与 D4 冲突——
> **收敛为「消融 A/B 对照实验」**（可解释、可复现、成本省 10 倍），保留 GA 的合理产物：
> S/N 位点分类（前缀敏感标记）+ golden 验证门。GA 名词保留为迭代组织的元框架。

## 一、染色体位点分类（保留——红线标记）

| 基因 | 值域 | 位点类 | 作用 |
|---|---|---|---|
| prompt | 预置变体 | **S（前缀敏感）** | 一次性 system 替换，变异=打穿缓存 |
| tools | 白名单子集 | **S** | 工具 schema 在前缀 |
| effort | low/medium/high | N（安全） | 推理深度，不影响前缀 |
| teammate 数 | 1..N | N | 并行度 |
| worktree | on/off | N | 写隔离 |
| 并发上限 | 1..32 | N | 调度 |

**纪律**：S 位点**禁止变异**（golden 字节对比门）；N 位点是消融实验对象。

## 二、适应度函数（衡量标准加权）

```
fitness = 0.4·成功率 + 0.2·(1/耗时) + 0.2·(1/token成本) + 0.2·前缀命中率
```

## 三、消融 A/B（替代全 GA）

对 N 位点**逐项**做基线 vs 单点变更对照（3-4 次/项）：
```
基线（R1 配置）→ 变更 effort: low→high → 重跑同基准 → 对比 fitness
→ 变更 teammate 数 1→3 → ... → 记录每项 delta
```
- **可解释**：每项变更的独立贡献清晰
- **可复现**：同基准同 N
- **成本**：单点 3-4 次 vs GA 30-40 次

## 四、进化闭环（保留）

```
任务 → 评估（fitness）→ 消融选择优胜 → 更新预置版本（vN+1）
→ 下代复用（配置 hash == manifest.current）
```

## 五、防虚假完成自检

| 检查 | 判据 |
|---|---|
| 每任务必有成绩 | results.jsonl 行数 == 任务次数 |
| 版本必有成因 | vN+1 标注 parent + mutation_source |
| 优胜必有证据 | fitness delta 记录 |
| 缓存红线 | S 位点零变异；golden 字节对比每轮 |
| 复用确实发生 | 下轮配置 hash == manifest.current |
