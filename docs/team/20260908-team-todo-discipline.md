# Team 任务确定性管理：todo 绑定纪律（2026-09-08）

**机制**：任何 team 编排（leader 派发研究员/写者任务）**必须与会话 todo 系统绑定**——
派发即登记、信封到达即签收、全部签收才汇总交付。**不依赖 leader"自觉"，由 todo 进度 + 签收门槛强制**。

## 确定性流程（每次 team 派发强制执行）

1. **派发前**：`todo_write` 为每个将派发的任务登记一项
   - 项标识 = teammate 名（zj-climate 等），content = 研究主题
2. **派发**：team add（任务进后台 job）
3. **签收**：每个任务完成 = P1 信封 `<background-job-result>` 到达你的会话轮次
   - 信封到达 → `complete_step` 签收该项（evidence = 信封/报告已收）
   - **未收到信封的任务绝不签收**（running 持续盯，不 declare 完成）
4. **全完成门槛**：仅当全部登记任务 complete_step 签收 → 才产出汇总交付
   - 缺任意一项未签 = 不允许 declare"全部完成"
5. **汇总交付**：逐任务给用户核心要点（引用信封全文位置）
6. **清场**：`group_delete`（登记为收尾项）

## 规则（禁止）

- ❌ 派发后不登记 todo（任务在系统里无跟踪 = 失职）
- ❌ 信封未到就 claim 完成（防虚假完成）
- ❌ 全部未签收就汇报"完成"
- ❌ 任务 running 时去写它独占路径（排队等锁——只读研究员不锁 leader，写者会）

## 与既有机制的关系

- P1 信封（结果确定性回 leader）= 签收证据源——机制已代码化
- 本纪律 = 让"leader 消化+汇报"也确定性（todo 门槛），补齐信封之后的模型行为空白
- 示例执行：2026-09-08 五主题研究（zj-climate/us-iran/quantum/food/religion）按此流程登记-签收-汇总

## 并发/安全备忘

- 只读研究员：并行、不锁 leader；写者：先 grant（路径级）串行
- 默认 ≤6 只读并行；任务 prompt 用 retrieve_info（缓存优先+联网兜底）
