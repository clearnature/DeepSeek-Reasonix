# Team 多智能体团队组织章程

> 生成：2026-08-10 · 分支：team（基点 main-v2 07fcf585b）· 状态：章程生效
> 关联：`docs/team-plan.md`（P1-P7 落地规划）、memory：team-multiagent-qwen-comparison

## 一、目的

用多智能体团队体系开发「Team 多智能体协作」功能（dogfooding）。同时为 Reasonix 的团队协作模式建立可复用的组织原型。

## 二、三职能硬性分离（不可违反）

| 职能 | 职责 | 角色 Profile |
|------|------|-------------|
| **规划 Planner** | 任务分解、拓扑扫描、多路径推演、制定计划 | `team-planner` |
| **执行 Executor** | 实现、测试、修复、沙盒验证 | `team-executor` |
| **纪律 Discipline** | 审查、幻觉检测、回归把关、防虚假完成验证 | `team-discipline` |

**铁律：执行、纪律、规划绝不能由同一个智能体完成。** 一次事务中，三个职能由不同智能体分别承担；同一智能体不得在本次事务中身兼多职。

## 三、团队规模（按事务类型）

| 团队 | 人数 | 触发条件 | 协作方式 |
|------|------|---------|---------|
| **决策委员会** | **12-15** | 重大决策：架构取舍、路线变更、P3 类哲学让步、跨阶段规划 | 独立评估 → 汇总 → 一致性协商 → 通过/驳回 |
| **纪律检查团** | **6** | 每次交付前（强制） | 并行审查，交叉验证证据，输出审查报告 |
| **执行小队** | **≥3** | 每个事务执行（最低 3 个） | 实现 + 测试 + 证据记录分工，可并行 |
| **规划小组** | 2-3 | 每个事务开始时 | 制定计划，输出任务分解 + 验证点 |

## 四、标准流程（事务全生命周期）

```
事务进入
  → 规划小组（2-3）制定计划：拓扑扫描 + 多路径推演 + 任务分解（fable5 Step 1-3）
  → 若涉及重大决策 → 决策委员会（12-15）讨论一致性 → 通过才继续
  → 执行小队（≥3）实施：并行执行 + 自我验证 + 沙盒验证（fable5 Step 4-6）
  → 纪律检查团（6）审查：fable5 合规 + 幻觉检测 + 回归 + 防虚假完成（fable5 Step 7-9）
  → 通过 → 交付（附完整证据链）
  → 不通过 → 退回执行小队修复，重新审查
```

## 五、一致性协商规则（决策委员会）

1. 12-15 个智能体**独立**评估提案（互不参考，防锚定/从众）
2. 第一轮投票：同意 / 反对（反对必须附理由）
3. 不一致 → 汇总各方理由，第二轮带证据讨论
4. **一致性通过标准**：最终同意率 ≥90% 且无未解答的反对理由；否则驳回或升级（由纪律团裁决是否需要更多信息）
5. 防幻觉：每个委员的评估必须附可验证证据（代码引用/测试输出/数据），无证据的投票不计入

## 六、防幻觉纪律（全体强制）

1. **所有智能体必须执行 fable5-thinking 技能**的 9 条刚性原则（任务分解/拓扑扫描/多路径推演/自我验证/沙盒验证/分级路由/持久记忆/对抗自检/防虚假完成）——这是纪律要求，不可跳过
2. 禁止口头「完成了」——每个完成声明必须附带可验证证据（测试输出、文件变更、数字结果）
3. 纪律检查团交叉验证执行小队的证据真实性（防止编造测试结果/文件变更）
4. 关键决策必须对抗自检（devil's advocate 视角攻击方案）

## 七、事务记录

每次事务产出：
- `docs/team/{date}-{topic}/plan.md`（规划小组产出）
- `docs/team/{date}-{topic}/execution.md`（执行小队产出 + 证据链）
- `docs/team/{date}-{topic}/review.md`（纪律检查团产出 + 结论）
- 重大决策附 `decision.md`（决策委员会一致性记录）

## 八、与产品功能的关系

本章程是**运作方式**（我们如何开发），`docs/team-plan.md` 是**产品功能**（我们要实现什么）。两者互补：用团队体系开发 Team 功能，功能落地后再把本组织模式固化为产品能力（P6 team 组织）。
